# CLAUDE.md

Guidance for Claude Code (or any AI assistant) working in this repository.

## Context

PayFlow Hub is an instant payments hub: event-driven microservices covering cash-in, cash-out, outbound notification, audit, and operational backoffice. See `docs/product/PRD.md` and `docs/technical/architecture/overview.md` before proposing structural changes.

## How work is conducted

- **Planned work** → PayFlow SDLC Kit (`.claude/`, fork of [wiz-cursor](https://github.com/NSXBet/wiz-cursor)): `/wiz-prd` (PRD via Q&A), `/wiz-phases` and `/wiz-milestones` (phases and milestones), `/wiz-next` (implementation with mandatory language-specialist review before commit), `/wiz-review-milestone` and `/wiz-review-phase` (on-demand audit), `/wiz-retro` (closes the phase), `/wiz-status`. See `.claude/NOTICE.md` and `/wiz-help`.
- **Isolated work** (bug, investigation, ad-hoc fix) → direct structured prompt, without going through commands. See `docs/technical/prompt-engineering.md`.

Principles that apply in both cases:

- **Document decisions, not just code.** Relevant architecture decisions become ADRs in `docs/decisions/`.
- **Small, descriptive commits.** Each commit reflects a coherent unit of work, with a message explaining why.
- **Test what you write.** New code in `services/payflow-backoffice-api` comes with tests (unit or e2e, as appropriate).

## Scope rules

- `services/payflow-backoffice-api` is the service with executable implementation. The others are specified and planned — do not generate implementation code for them without aligning first.
- **`docs/` at the repository root is the single source of truth.** No service has its own `docs/` folder. Language specialists (`.claude/agents/wiz-*-specialist.md`) carry a generic preferred stack as fallback, but must explicitly defer to `docs/technical/guidelines/` whenever there is a conflict — an agent that applies its own default without checking the documented guideline is an agent bug, not a valid second opinion.
- Service-specific context goes in `.wiz/<slug>/` (planning state generated by `wiz-*` commands) or in the service's own README, never in a copy of `docs/`.
- No data, client names, credentials, or business logic from real systems may be referenced in this repository.

## Technical conventions

See `docs/technical/guidelines/` (coding-standards, dependency-injection, error-handling, logging) and `docs/technical/ci-cd.md` (quality gates, minimum coverage, pipeline).
