# PayFlow Hub

Reduced-scope instant payments hub — event-driven microservices covering cash-in, cash-out, outbound webhook notification, audit trail, and operational backoffice.

This repository documents the full software lifecycle with AI integrated into the process: from PRD to architecture, from traceable planning to implementation, code review, and retrospective. Domain, names, and data are fictional.

## How AI fits into the cycle

Two distinct regimes, with distinct tools:

- **PayFlow SDLC Kit** ([`.claude/`](./.claude)) — agents and commands that drive planned work, a fork adapted from [wiz-cursor](https://github.com/NSXBet/wiz-cursor) (see [`.claude/NOTICE.md`](./.claude/NOTICE.md)). `/wiz-prd` generates the PRD via Q&A; `/wiz-phases` and `/wiz-milestones` break it into traceable phases and milestones; `/wiz-next` implements each milestone with mandatory language-specialist review before commit; `/wiz-review-milestone` and `/wiz-review-phase` audit on demand; `/wiz-retro` closes the phase, deciding per finding whether it becomes accepted debt, a guideline update, or an ADR.
- **Structured prompt** ([`docs/technical/prompt-engineering.md`](./docs/technical/prompt-engineering.md)) — for work that does not fit a planned milestone: bug fix, ad-hoc investigation, isolated architecture decision.

What ties both together is the single-source rule: [`docs/`](./docs) is the only origin of technical standards. No service has its own `docs/`, and no agent carries its own conventions — both reference the same place, keeping humans and AI reading the same thing.

## Structure

```
payflow-hub/
├── .claude/
│   ├── agents/wiz-*.md             # planner, reviewer, milestone-analyst, retro-analyst, language specialists
│   ├── commands/wiz-*.md           # /wiz-prd, /wiz-phases, /wiz-milestones, /wiz-next, /wiz-review-*, /wiz-retro, /wiz-status
│   └── NOTICE.md                   # origin (wiz-cursor fork) and adaptations in this repository
├── .wiz/
│   ├── context/                    # authoritative-sources.md — points planning at docs/technical/guidelines/
│   └── <slug>/                     # one directory per PRD (e.g. backoffice-api/), generated by wiz-* commands
│       ├── prd.md
│       ├── phases/phaseN.md        # milestones in P0XM0Y format
│       ├── reviews/                # review note per completed milestone/phase
│       └── retros/                 # retrospective per closed phase
├── docs/
│   ├── product/PRD.md              # product, personas, NFRs
│   ├── technical/
│   │   ├── architecture/           # overview, security, observability
│   │   ├── infrastructure/         # AWS, SRE runbook
│   │   ├── guidelines/             # DI, error handling, logging, coding standards
│   │   ├── quality/                # QA guidelines + AI process metrics
│   │   ├── ci-cd.md                # pipeline and quality gates
│   │   ├── ai-augmented-sdlc.md    # the full cycle, phase by phase
│   │   ├── prompt-engineering.md   # structured prompt and context management
│   │   ├── versioning.md           # SemVer per service, changelog, contract deprecation
│   │   └── retrospective.md        # when and how guidelines evolve
│   ├── contract/                   # API/event conventions
│   └── decisions/                  # ADRs
├── services/
│   ├── payflow-gateway/            # edge: authentication, rate limit, routing
│   ├── payflow-cashin-service/     # payment intake
│   ├── payflow-cashout-service/    # payment payout
│   ├── payflow-webhook-service/    # outbound notification with retry and DLQ
│   ├── payflow-outbox-relay/       # reliable event publishing (outbox pattern)
│   ├── payflow-audit-service/      # append-only audit trail
│   └── payflow-backoffice-api/     # operational API (NestJS) — query and reconciliation
├── PULL_REQUEST_TEMPLATE.md        # PR checklist: consulted context + review note
├── CONTRIBUTING.md                 # onboarding: reading order, first milestone, common mistakes
└── CLAUDE.md                       # AI guidance for this repository
```

`payflow-backoffice-api` is the service with executable implementation. The others are specified and planned — contract, events, and milestones defined, ready for execution.

## How to read this repository

1. [`docs/product/PRD.md`](./docs/product/PRD.md) — product context, personas, and prioritized NFRs.
2. [`docs/technical/architecture/overview.md`](./docs/technical/architecture/overview.md) — architecture overview, with links to security, observability, and infrastructure.
3. [`docs/technical/ai-augmented-sdlc.md`](./docs/technical/ai-augmented-sdlc.md) — the full AI-assisted cycle, phase by phase.
4. [`.wiz/backoffice-api/prd.md`](./.wiz/backoffice-api/prd.md) and [`.wiz/backoffice-api/phases/`](./.wiz/backoffice-api/phases) — end-to-end traceability for the only service with implementation: PRD, phases, and milestones generated by the PayFlow SDLC Kit.
5. [`CONTRIBUTING.md`](./CONTRIBUTING.md) — how a new developer (or a fresh AI session) enters the workflow.

## Stack

- **Domain services**: Go, hexagonal architecture, asynchronous communication via Kafka
- **Backoffice API**: Node.js, NestJS, TypeScript
- **AI**: Claude Code — see [`docs/technical/ai-augmented-sdlc.md`](./docs/technical/ai-augmented-sdlc.md)
